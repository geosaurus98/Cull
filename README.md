# Cull

A local-first web app for deciding which of your belongings to get rid of, based on **when you last used them** and **what each use has cost you**.

- No backend, no accounts. Everything is stored in your browser's IndexedDB (via Dexie) and never leaves the device.
- Installable as a PWA and works fully offline.
- Built with Vite, React, TypeScript, Tailwind, Dexie and Vitest.

## Running it

Requires Node 18+.

```bash
npm install
npm run dev        # dev server at http://localhost:5173
npm test           # unit tests (scoring, last-used mapping, formatting, maybe review, price parsing)
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build at http://localhost:4173
```

The service worker is only generated by `npm run build`, so test offline and install behaviour with `npm run preview` (or any static host), not `npm run dev`.

To try it on your phone over your LAN, run `npm run build && npx vite preview --host` and open the printed network URL. Browsers only allow service workers on `https://` or `localhost`, so a plain LAN IP works for trying the app but **won't install offline**. For the real install, deploy `dist/` to any static HTTPS host (GitHub Pages, Netlify, Cloudflare Pages, etc.). The build uses relative paths, so it also works from a sub-path.

## Installing as an app (PWA)

1. Open the deployed HTTPS URL on your phone.
2. **iPhone / iPad (Safari):** Share → **Add to Home Screen**.
   **Android (Chrome):** ⋮ menu → **Install app** (or **Add to Home screen**).
   **Desktop Chrome / Edge:** the install icon in the address bar.
3. Launch it from the home screen. It runs full-screen and works offline. Updates install automatically the next time you open it online.

Your data is tied to that browser on that device. Use **Stats → Settings → Export backup** regularly. The JSON file includes photos as base64 and can be imported on another device. Import **replaces** everything currently stored.

## Screens

| Tab | What it does |
| --- | --- |
| **Cull** | Every undecided item, sorted by cull score (highest first). Tap **Keep / Maybe / Out**, or swipe right to keep and left to throw out. Every decision shows an **Undo** toast. |
| **Add** | Only the name is required. Add a photo (camera or library; resized to ≤800px JPEG), a room (autocompletes, with one-tap chips for existing rooms), a price, and "last used (roughly)". After saving, the form stays open with the room kept, so you can add items quickly. |
| **Items** | Search by name, filter by room and status, sort. **✓ Used it** logs a use and resets "last used". Tap an item to edit it, change its status or delete it. |
| **Maybe** | Items you parked. Each one has a review date (by default 30 days after you parked it; you can change the default and each item's date). When review dates pass, a banner appears across the app. The suggested action is **Out** for anything not used since it went in the box, with a one-tap "Mark N unused as Out". |
| **Stats** | Counts by status, a remaining/decided bar, total purchase value of items marked Out, and a per-room breakdown. The **Settings** link (currency symbol, default maybe review days, backup/import, delete all data) is here. |

Dark mode follows your system setting.

### "Last used (roughly)" mapping

| Option | Treated as |
| --- | --- |
| Today | now |
| This week | 3 days ago |
| This month | 14 days ago |
| 3 months ago | 91 days ago |
| 6 months ago | 182 days ago |
| A year ago | 365 days ago |
| 2+ years ago | 730 days ago |
| Can't remember | 1095 days ago (3 years), and the item shows "can't remember" until you first tap **Used it** |

## How the cull score works

The score is a number from 0 to 100. Higher means a stronger candidate for getting rid of. It is a pure function in [`src/lib/score.ts`](src/lib/score.ts), tested in `src/lib/score.test.ts`.

```
score = 75 × staleness + 25 × costFactor

staleness  = min(daysSinceLastUsed, 1095) / 1095                  // linear, capped at 3 years
costPerUse = purchasePrice / max(numberOfUses, 1)
costFactor = min(log10(1 + costPerUse) / log10(1 + 1000), 1)      // log scale, caps at 1000 per use
```

- **Staleness dominates.** It is worth up to 75 points. An item untouched for 3+ years gets all 75.
- **Cost per use** is worth up to 25 points. It uses a log scale, so 10 → 100 per use counts about as much as 100 → 1000 per use. Higher cost per use means worse value, so the score goes up.
- **Items with no price** get 0 cost points and rank on staleness alone.
- **No recorded uses** counts as one use, so cost per use equals the purchase price.
- **Ties** are broken by least recently used first, then name, then id, so the order is stable.

One consequence: an expensive item you used today but haven't logged any uses for yet (for example a new $80 knife) gets cost points straight away (about 16). It can therefore rank above a cheap item last used a couple of weeks ago. Tapping **Used it** a few times brings its cost per use down, and anything genuinely stale will still outrank it.

To tune the weights, change `STALE_WEIGHT`, `COST_WEIGHT`, `STALE_CAP_DAYS` and `COST_CAP` at the top of `score.ts`.

```
src/
  App.tsx, router.ts         tab shell + hash routing
  lib/
    types.ts                 Item, Status, Settings
    db.ts                    Dexie schema + live-query hooks
    score.ts                 cull score + sort (pure, tested)
    lastUsed.ts              dropdown → date (pure, tested)
    maybe.ts                 review-due logic (pure, tested)
    format.ts, parse.ts      time-ago, money, dates, price parsing (pure, tested)
    actions.ts               add / decide / undo / mark used
    image.ts                 photo resize to ≤800px JPEG
    backup.ts                JSON export/import
  components/                cards, swipe, toast/undo, pickers
  screens/                   Candidates, AddItem, AllItems, MaybeBox, Progress, Settings
public/                      icons (regenerate PNGs with `npm run icons`, needs Playwright)
```
